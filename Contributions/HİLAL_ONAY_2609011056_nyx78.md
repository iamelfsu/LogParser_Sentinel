# My Contributions 

 For this project, I developed the CLI (Command Line Interface) layer that manages user interaction and command dispatching. 

* **Parameter Definition:** Using the `argparse` library, I defined the command-line parameters for our LogParser-Sentinel tool[cite: 1].
* **Input/Output Handling:** Made the `--log` parameter mandatory for the target log file path and set `--output` to default to `crisis_report.txt` if omitted[cite: 1].
* **Error Prevention:** Handled invalid CLI commands using a `try-except SystemExit` block to print an informative "Hint" message and safely exit via `sys.exit(1)` instead of crashing[cite: 1].
* **Execution Flow:** Passed arguments to `analyze_log()` to obtain a results dictionary, then forwarded the output to `generate_crisis_report()` to trigger report generation[cite: 1].
* **Entry Point Control:** Secured execution using an `if __name__ == '__main__':` check to prevent unintended execution on import[cite: 1].

---
Secondly, I developed the `log_generator.py` module to automatically generate realistic log data required for testing phases:

* **Library Integration:** Imported Python's built-in `random`, `datetime`, and `timedelta` libraries to manage randomized data distribution and chronological timestamps.
* **Parameterized Generation:** Created the `generate_log()` function taking `file_name` and `line_count` parameters (defaulting to 10,000 lines).
* **Mock Data Pools:** Defined local IP pools, a static `attacker_ip`, web route endpoints, and system log levels (`INFO`, `WARNING`, `ERROR`, `CRITICAL`) with probability weights (`85%`, `12%`, `2.5%`, `0.5%`) to mimic real-world server routines.
* **Chronological Simulation:** Established a time reference point starting 1 day ago, incrementing timestamps randomly between 0.1 and 2 seconds per line using `timedelta`.
* **Context Manager Usage:** Utilized a `with open()` block to ensure the log file is safely managed and automatically closed by the operating system.
* **Conditional Log Formatting:** Dynamically formatted log lines based on selected levels—generating user page views for `INFO`, memory capacity warnings (`75-89%`) for `WARNING`, timeout errors for `ERROR`, and database disconnections for `CRITICAL`.
* **Cyber Threat Scenario:** Implemented a targeted attack injection where loop iterations between specific line thresholds (50,000–50,015) log an unauthorized admin panel access attempt from the attacker's IP.
* **Entry Point Control:** Secured script execution using an `if __name__ == '__main__':` check to trigger generation directly from the terminal.
